# TraceBug - project memory for Claude Code

Local-first bug-capture tool: MV3 browser extension + npm SDK + stdio MCP CLI. MIT. No backend.

## Layout
- `src/` - SDK (TypeScript). Built with tsup into the extension bundle.
- `cli/` - MCP CLI entry (`cli/bin.ts` -> `dist/bin.mjs`, published as `packages/tracebug/`).
- `tracebug-extension/` - MV3 extension: `manifest.json`, `background.js` (service worker), `content-script.js`, `offscreen.*` (MediaRecorder), `popup.*`, `player.*`, `tracebug-init.js`. Packaged builds land in `tracebug-extension/dist/{chrome,firefox}`.
- `tracebug-extension/tracebug-sdk.js` and `tracebug-extension/tracebug-provider-api.js` - **both generated by
  `npm run build` (tsup). Never edit by hand.** The second is the provider HTTP layer (`src/providers/api.ts`)
  bundled for the background service worker, which cannot import the page SDK.
- `tests/` - Vitest unit tests (e.g. `tests/storage.test.ts`). `e2e/` - Playwright specs + `.e2e.mjs` scripts; benchmark at `e2e/benchmark.mjs`.
- `docs/` - user docs; `docs/adr/` - architecture decisions (read the relevant ADR before changing architecture).
- `docs/launch/` - current launch work: `STATE.md` (where things stand - **start here**), `PLAN.md` (what's left), `PROGRESS.md`. The `*-archive.md` files are closed history; don't read them unless you need why.

## Commands
- **All gates: `node scripts/check.mjs`** (`--full` if extension files changed, `--firefox` at the end of a phase). One line per gate, full output only on failure. See the `gates` skill; don't run the npm scripts one by one.
- Build SDK + extension bundle: `npm run build` (tsup; rewrites `tracebug-extension/tracebug-sdk.js`, then reload the unpacked extension)
- Single test file: `npx vitest run tests/storage.test.ts --reporter=dot` | e2e: `node e2e/<name>.e2e.mjs` (run only the related suite)
- Benchmark: `node e2e/benchmark.mjs`

## Hard rules
- No backend, no telemetry, no remote loads in exported `.html` (ADR 001, 002).
- Zero runtime dependencies (ADR 005). MV3 only (ADR 004). MCP is stdio only (ADR 006).
- Never add a manifest permission without asking. Removing or making optional is fine.
- Keep storage invariants in `docs/ticket-flow.md` and `tests/storage.test.ts`: never evict saved tickets, verify writes before showing "Saved".
- Keep Firefox 128+ working; branch on feature detection, not on user-agent strings.
- In extension mode the SDK runs in the page's main world: page `localStorage` is readable by the host site. Never store secrets there.

## Git
- Work on `develop`. Do not commit - leave changes uncommitted and suggest a commit message.
- No `Co-Authored-By` trailers.

## Working style (saves tokens)
- Doing launch work? Use the **`phase`** skill. Verifying anything? Use **`gates`**.
- Before exploring, read `docs/launch/STATE.md`, then `docs/launch/CODEMAP.md` to find the code; don't re-investigate what they already answer.
- Use `rg`/grep with paths; read specific line ranges, not whole large files (`docs/api-reference.md`, `ARCHITECTURE.md` and the built bundle are big).
- Make small diffs. Run only the tests related to the change, then the full suite once at the end of a phase.
- At the end of each phase, rewrite `docs/launch/STATE.md` and add a <=5 line entry to `docs/launch/PROGRESS.md` (what changed, files, how verified, open issues).
