Applied: #1, #2, #6, #7, #9–#13. Deferred: #3, #4. #5 is pending a proposal. #8: the revert stubs were kept. #14–#16 were not approved.

- **#1 correction: 14.2.35 is not a full fix.** The "fix available → 14.2.35" line came from `npm audit` itself, and I misread it as resolving everything. After the bump, `npm audit` still reports **25 Next advisories, 3 of them critical** (Image Optimization API RCEs via AVIF/SVG, plus an RCE on Windows-hosted servers). Every one needs `next` ≥ 15.5.28, so they can't be fixed on the 14.x line. The 14.2.35 bump stays because it's strictly better than 14.2.5, and `next build` passes. The non-force `npm audit fix` cleared everything except `next` and its nested `postcss`. **The real fix is a major upgrade (15.5.28+ or 16). Decision: not now.**
- **#1 mitigation (follow-up, same day): the image optimizer is turned off.** `website/next.config.js` now sets `images: { unoptimized: true }`, and the `formats` line is gone. That's safe because nothing imports `next/image`: `git grep "next/image"` over `app components lib` finds only a comment at `components/Testimonials.tsx:63` saying it's deliberately not used. Of the 3 criticals:
  - **GHSA-2xp9-vwfh-vxw4 (AVIF) and GHSA-2464-fhr4-w9xw (SVG) are optimizer-only.** Both are `sharp`/`libheif` bugs reached through the Image Optimization API (`gh api advisories/<id>`). **Closed by this change.**
  - **GHSA-p293-qw3h-jr36 is not image-related.** It's an RCE in the Pages and App routers when the server is "hosted on machines using a Windows filesystem", with "no known workaround". Production runs on Netlify (Linux functions), so it isn't reachable there. A `next start` on a Windows dev machine is exposed if it's reachable from the network. **Still open, and only an upgrade fixes it.**
  - **Verified locally:** `next build` passes (61 pages, middleware 27.1 kB). On `next start`, `/_next/image?url=…&w=640&q=75` → **404** for `.jpg`, `.png` and `.svg` sources, while the same `.jpg` served statically → 200 `image/jpeg`.
  - **Production, before deploy:** the live `/_next/image` returns 200 with `Netlify-Vary: query=…url|w|width…`, which means Netlify Image CDN serves that path, not Next's `sharp` optimizer. So the two image RCEs most likely never ran in production. They do apply to any self-hosted `next start`.
  - **After deploy, check by hand** that the live URL stops serving. `@netlify/plugin-nextjs` decides that routing, and it can't be observed from here.
  - The other 22 non-critical Next advisories (DoS, cache poisoning, SSRF in rewrites/Server Actions) remain until the upgrade.
- **#2:** `tracebug-sdk-ext.js` went from 3,454,292 to **1,988,928 bytes**. `ext:lint` warnings fell from 26 to 14, and the baseline was lowered to match.
- **#7:** `runReportPlugins` and `runExportPlugins` were **kept**. They aren't dead code: they're the runners for the `onReport` / `onExport` plugin hooks that `docs/api-reference.md:620-639` documents, and nothing calls them, so **those documented hooks never fire. None of the other 19 names appear in `docs/api-reference.md`.
