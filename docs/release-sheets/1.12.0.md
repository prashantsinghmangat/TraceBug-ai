### Privacy tab

**Single purpose:**
```text
TraceBug captures a browser bug on the tab where the user starts a capture: a replay of their clicks, inputs and navigation, the console errors, the network requests, and optionally a screen recording with microphone narration. It turns them into one bug report the user can review, save on their device, export as a file, or send to their own issue tracker or AI tool. On request it also audits that page for accessibility, layout, performance and SEO problems, so they can be reported and fixed the same way.
```
**Permission justifications** — one box per permission:

`activeTab`
```text
Lets TraceBug act only on the tab the user is looking at when they click Capture, Screenshot or Audit this page, or press the Alt+B shortcut: it injects the capture script there, takes the screenshot, or runs the page audit. It gives no access to any other tab.
```
`storage`
```text
Keeps the user's settings (record options, chosen microphone, redaction rules), the integration tokens they enter, and a finished screen recording on their own device, plus the state of a running capture so it survives the service worker restarting.
```
`unlimitedStorage`
```text
TraceBug stores bug-capture sessions (screen recordings, DOM replay events and screenshots) locally in the user's browser until the user exports or deletes them. A single capture can be several megabytes, so the default storage quota would cut recordings off mid-session. The data stays on the user's device and is never sent to TraceBug; it leaves the device only when the user exports it or sends it to a service they chose.
```
`scripting`
```text
Injects TraceBug's capture script and its stylesheet into the current tab, only after the user starts a capture or a screenshot, and the packaged accessibility checker (axe-core, part of the extension package) only when the user runs a Site Audit. Nothing is injected automatically or in the background, and no code is loaded from outside the package.
```
`alarms`
```text
Closes an unanswered "Send this report to GitHub / Linear / Slack?" confirmation window after two minutes, so a send the user never approved can't be confirmed later. A Manifest V3 service worker can't hold a timer that long on its own.
```
`offscreen`
```text
Hosts the MediaRecorder for the optional screen recording the user starts ("Events + Video"). A service worker has no media APIs, and the recording must keep running while the user navigates the recorded tab. The document is created when the recording starts and closed when it stops.
```
`tabCapture`
```text
Records the tab the user opened TraceBug on when they start a recording in Tab mode (the default), without Chrome's "Choose what to share" dialog. Used only after the user clicks Start, and only for that tab; nothing is recorded in the background. The recording stays on the user's device unless they export or share it. Desktop mode does not use this permission and still shows Chrome's share dialog. Required rather than optional because Chrome only issues a tab stream ID for a tab the extension was invoked on while it already held this permission, so a runtime grant could never record the tab it was granted on.
```
Host permissions (optional):
```text
Requested when the user saves a GitHub, Linear, Slack, OpenAI, Anthropic or Ollama integration (one fixed address each, or `localhost`/`127.0.0.1` for Ollama), so TraceBug can send the report to that service. Declared optional so TraceBug can request access to one specific address you enter for a self-hosted AI provider, only at the moment you save it, and never for all sites.
```
**Remote code:** No, I am not using remote code.

**2. Safety check.** Website fixes are often made on `main` and copied to `develop`, so the same change has two histories
and conflicts with itself. Keeping `develop`'s side is safe only for files whose `main` version is already in `develop`'s
history. Every line must say `on develop`; for any `MAIN ONLY` file, merge that file by hand instead:
```bash
for f in $(git merge-tree --write-tree --name-only develop origin/main | sed -n '2,/^$/p'); do b=$(git rev-parse "origin/main:$f"); git --literal-pathspecs rev-list develop -- "$f" | while read c; do git rev-parse -q --verify "$c:$f"; done | grep -qx "$b" && echo "on develop  $f" || echo "MAIN ONLY  $f"; done
```

**Notes:**
```markdown
> Site Audit (plan: `docs/audit-quality/implementation-plan.md`): check the page you are on, re-run to see what changed, and hand the audit to a coding agent.

### Added

- **Site Audit.** The popup's **Audit ▾** menu offers All checks, **Auto Review** (broken layout and images, errors, failed requests, dead and rage clicks), **Accessibility Audit** (axe-core plus a keyboard pass: positive `tabindex`, focus landing on invisible elements, CSS that hides the focus outline) and **Performance & SEO**; the panel switches between them. It checks the page you are on for accessibility (axe-core 4.11, WCAG 2.0–2.2 A/AA), layout (sideways scroll and its cause, overlapping or clipped elements, images without size, broken images), performance (this load's TTFB, FCP, LCP, CLS, page weight, large and render-blocking files — lab values, not real-user data), SEO (title, description, canonical, h1, noindex, viewport) and errors seen in the capture. Each check says what it can't tell you, and a check that could not run shows "Not run", never "no issues". **Re-run audit** shows what was fixed, what is still there, what is new and what regressed. axe-core is a separate packaged file loaded only when you run an audit.
- **Audit score.** Every run gets a 0–100 score per category and overall, coloured green (90+), amber (50–89) or red (below 50). The formula is one click away: each distinct problem takes a share of what's left — critical 20%, serious 12%, moderate 6%, minor 2% — and a quarter more per extra element, up to double. Checks that didn't run are never scored. It's computed from every finding, including any left out of the list, and it's not a WCAG conformance grade. Calibrated on ten public sites: gov.uk 94–100, MDN 76, GitHub 50, Hacker News 24.
- **Fewer, better findings.** Tested against ten public sites, the audit now reports half as many findings, and what it drops was noise: text hidden for screen readers or skip links reported as "cut off", custom checkboxes reported as invisible focus, Tailwind `focus:outline-none` + `focus:ring` and `:focus:not(:focus-visible)` reported as a missing outline, card links reported as label-in-name failures, overlaps where both controls still get their clicks, images whose CSS already reserves the space, and dev-server bundle sizes on localhost. An overlap is now only reported when the covered control really can't be clicked, and controls inside a hidden (opacity 0) menu are no longer checked. Errors and dead clicks are only reported for the page being audited (not one visited earlier in the same session), and the accessibility result says which colour theme it checked, so a light/dark site gets a run in each.
- **Audit panel docks to the side and stays open.** It sits beside the page (right or left, your choice), so **Locate on page** scrolls to the element and highlights it without closing the list. It can be minimised to a small tab showing the score, and **dragged anywhere by its header** — the spot is remembered, and dropping it at the left or right edge docks it again. The floating toolbar has an **Audit** button that opens and closes it. In the popup, **Audit this page** is now the first, largest card (one click runs all checks; the arrow opens the four scans, each with an icon), above Capture Screenshot and Capture Bug. The header shows the score, a WCAG line that only states failures ("WCAG A/AA: 2 criteria fail" — never a "pass" automated checks can't prove), counts by severity (critical / high / medium / low, click to filter), how many accessibility rules passed, and per-category scores you can click to filter. Findings are grouped by rule ("Low contrast · 15 elements"), each with what's wrong, a Found / Required table, the WCAG criterion, how to fix it, and every element with Locate and Copy selector.
- **Copy for AI.** Tick the findings you want and copy them as one fix prompt for Claude Code, Cursor or any coding agent: rule, WCAG criterion, element, measured values and fix for each, with page text marked as data.
- **Every finding says how to fix it and where it is**, with its WCAG criterion (e.g. "1.4.3 Contrast (Minimum)"). Contrast findings show the measured colours and the nearest text colour that passes (for example `#b45309` → `#ad5009` on `#f4eae4`); the suggested colour is re-checked so it never misses the ratio.
- **Site Audit docs.** A full guide (`docs/site-audit.md`), an "Audit a page" section in the website docs, a Site Audit tab on the home page, the API reference for `runAudit`, `showAuditPanel`, `exportAudit` and `compareAudits`, and `docs/AGENT-BRIEF.md`, a one-page brief to hand any AI agent working on or with TraceBug.
- **More accessibility checks:** Label in Name (WCAG 2.5.3, axe's own rule, off by default in axe) and a fixed or sticky header that can hide focused elements (WCAG 2.4.11).
- **More SEO and performance checks**, chosen by comparing against Rank Math, Seobility, SEOptimer and DotPlus on the same page and keeping only what they got right: social preview tags (missing `og:image`, `og:title`/`og:description`, relative `og:image`, no `twitter:card`), structured data that doesn't parse or has no `@type`, **robots.txt blocking the page** (critical — the audit reads this site's `/robots.txt`, and `/sitemap.xml` only if robots.txt names no sitemap), no sitemap, images with 4× more pixels than even a retina screen needs, and JPEG/PNG over 100 KB that WebP/AVIF would shrink (using the type the server really sent, so image CDNs aren't misreported). It still doesn't flag `alt=""` on decorative images, which all four of those tools wrongly report as missing alt text.
- **Scores checked against Lighthouse 12.8** on ten public sites. Added **main-thread blocking** (Total Blocking Time, computed the way Lighthouse does, for the page load only; Chrome-based browsers): heavy-script pages like Stripe and Shopify had read 94 and 80 for performance with no blocking check. Layout shift (CLS) is now the worst burst of shifts, as web-vitals and Lighthouse define it, not the sum over the whole visit (Shopify read 0.577; Lighthouse reads 0, and so do we now). Accessibility scores stay stricter than Lighthouse on purpose: the same rule failing on more elements costs more.
- **Phone width.** All checks and Auto Review now also check the page at 390 px wide — in a hidden, same-site frame, so you don't have to resize your window — and report only what goes wrong there and not at your current width: the page scrolling sideways (WCAG 1.4.10 Reflow), elements wider than the screen, cut-off text, covered buttons, and scrolling boxes keyboard users can't reach (WCAG 2.1.1). It's a second page load, which the panel says; sites that forbid framing show "Not run" with the reason, never "no problems". On tracebug.dev it finds the two code blocks that scroll only on phones.
- **Needs a person to check.** What axe couldn't decide on its own (text over an image or gradient, an `aria-label` on a plain `<span>`) is listed in a collapsed section with the reason, the WCAG criterion and each element to locate — never counted as a failure and never in the score. It's in the exported report and in MCP `get_audit` as `needsReview`.
- **Text that fades in on scroll is no longer silently skipped.** The audit says how much text was invisible when checked, and **Scroll the page and re-run** reveals it, checks it, and puts you back where you were.
- **Audit reports for coding agents.** **Export report** downloads the audit as the usual self-contained `.html` (it opens on an Audit tab). The MCP server reads it with three new tools: `get_audit`, `get_finding` (evidence and search hints, optionally searched literally in your repo) and `compare_audits` (before/after a fix). Text from the audited page is marked `untrusted` so agents treat it as data. `list_bug_reports` now says whether a file is a bug or an audit. `get_audit` includes the scores and their formula; `get_finding` includes the WCAG criteria and the suggested fix.
```
