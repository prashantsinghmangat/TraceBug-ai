### Privacy tab

**Single purpose:**
```text
TraceBug captures a browser bug on the tab where the user starts a capture: a replay of their clicks, inputs and navigation, the console errors, the network requests, and optionally a screen recording with microphone narration. It turns them into one bug report the user can review, save on their device, export as a file, or send to their own issue tracker or AI tool.
```
**Permission justifications** — one box per permission:

`activeTab`
```text
Lets TraceBug act only on the tab the user is looking at when they click Capture or Screenshot, or press the Alt+B shortcut: it injects the capture script there and takes the screenshot. It gives no access to any other tab.
```
`storage`
```text
Keeps the user's settings (record options, chosen microphone, redaction rules), the integration tokens they enter, and a finished screen recording on their own device, plus the state of a running capture so it survives the service worker restarting.
```
`unlimitedStorage`
```text
TraceBug stores bug-capture sessions (screen recordings, DOM replay events and screenshots) locally in the user's browser until the user exports or deletes them. A single capture can be several megabytes, so the default storage quota would cut recordings off mid-session. The data stays on the user's device and is never sent to TraceBug; it leaves the device only when the user exports it or sends it to a service they chose.
```
`scripting`
```text
Injects TraceBug's capture script and its stylesheet into the current tab, only after the user starts a capture or a screenshot. Nothing is injected automatically or in the background.
```
`alarms`
```text
Closes an unanswered "Send this report to GitHub / Linear / Slack?" confirmation window after two minutes, so a send the user never approved can't be confirmed later. A Manifest V3 service worker can't hold a timer that long on its own.
```
`offscreen`
```text
Hosts the MediaRecorder for the optional screen recording the user starts ("Events + Video"). A service worker has no media APIs, and the recording must keep running while the user navigates the recorded tab. The document is created when the recording starts and closed when it stops.
```
`tabCapture`
```text
Records the tab the user opened TraceBug on when they start a recording in Tab mode (the default), without Chrome's "Choose what to share" dialog. Used only after the user clicks Start, and only for that tab; nothing is recorded in the background. The recording stays on the user's device unless they export or share it. Desktop mode does not use this permission and still shows Chrome's share dialog. Required rather than optional because Chrome only issues a tab stream ID for a tab the extension was invoked on while it already held this permission, so a runtime grant could never record the tab it was granted on.
```
Host permissions (optional):
```text
Requested when the user saves a GitHub, Linear, Slack, OpenAI, Anthropic or Ollama integration (one fixed address each, or `localhost`/`127.0.0.1` for Ollama), so TraceBug can send the report to that service. Declared optional so TraceBug can request access to one specific address you enter for a self-hosted AI provider, only at the moment you save it, and never for all sites.
```

Releases → Draft a new release → tag `v1.11.6`.

**Title:**
```text
TraceBug 1.11.6
```
**Notes:**
```markdown
> Evidence integrity (plan: `docs/launch/master-plan.md` Part 3, developed as "1.12") and fewer dead ends between a captured bug and an AI fix (`docs/launch/minimum-click-workflow.md`).

### Added

- **A report-quality benchmark gates every release.** `e2e/report-quality.e2e.mjs` captures five bugs on a small shop with the real extension (a crash followed by an unrelated click, a 422 after a quantity change, a wrong total with no error, a 404 followed by an unhandled rejection, a clean session) and checks each report against an answer key: the action named in the title, only real failures, the response body, the order of events, no invented cause, the evidence block, prompt size, and no secret anywhere in the report, prompt, `.html` or replay. It runs in `node scripts/check.mjs --full`. Its first run found the three leaks fixed below.

- **Every report says what it captured, what it didn't, and what it lost.** An "Evidence" block lists what was captured (actions, errors, requests, screenshots, replay, video), what is never captured (request/response bodies beyond 200 characters of a failed response, headers, iframe and canvas content, successful asset loads, console levels that were off), what was masked, and what was dropped (evicted early events, console output past 50 per level, video past the 2-minute limit, replay of earlier pages, failed responses with no body). It appears in the ticket's Info tab, the exported `.html`, the Fix with AI prompt ("Evidence coverage") and the MCP `get_bug_report` (`evidence`), whose investigation guide lists the gaps. "No errors captured" now adds "the capture is incomplete, so an error may have been missed" when early events were dropped or console capture was off.

### Fixed

- **Only real failures are reported as failures.** A request with status 0 was "failed" everywhere, but status 0 also means three things that aren't failures: a browser timing record whose status isn't exposed (every Firefox row, and cross-origin rows without `Timing-Allow-Origin`), a fetch or XHR the app aborted, and an opaque `no-cors` response. Each became "API … failed with Network Error" at **high** confidence, sending the reader and the AI after a failure that never happened. Aborted and opaque requests are now tagged at capture, timing rows keep "status unknown", and one rule (`src/request-status.ts`) decides failure for the report, title, summary, root-cause hint, timeline, repro steps, AI prompt and MCP. The Network tabs show "aborted", "opaque" or "—" instead of a red ERR, and `get_network_activity` explains each.
- **The clicks that lead up to a bug are no longer pushed out.** A session keeps its newest events and drops the oldest, and the browser's timing records of every image, font and fetch were filling that space while you reproduced the bug, so the clicks that caused it could be the first thing dropped. During a capture, a fetch/XHR is now recorded only by its wrapper (which has the method and status; the timing copy was always discarded later anyway), and an image, script or font only when it failed or was slow, the same rule page-load requests already followed.
- **Typing right before a click is recorded before the click.** A typed value is recorded 300 ms after the last keystroke, so clicking "Apply" quickly put the click ahead of the value it applied, and a value typed just before Stop or leaving the page was lost. Pending typing is now written out the moment you press a mouse button or Enter, leave the page, or stop.
- **Tokens in the page URL no longer leak through error stacks.** An inline script's stack frames carry the page URL, query string included, so `?access_token=…` reached the report, the AI prompt and the exported file. Sensitive params are now masked in every URL inside captured text (stacks, console messages, response snippets) and in the error's source URL; the frame's line and column are kept.
- **Hidden form fields are out of the DOM replay.** Masking inputs covered typed values but not an `<input type="hidden">`'s value, so CSRF tokens rode into every replay. Hidden inputs' values are now dropped from snapshots and later changes.
- **The browser's favicon request is never one of the report's failures.** A missing `/favicon.ico` counted as a failed request in the evidence block and the exports. It stays in the Network tab.
- **Reports see the newest events.** Events are written to storage about a second after they happen, and the repro steps built on an error (and a report built right after a click) read storage, so the click that triggered the bug could be missing. Reads now include unwritten events, and the repro steps are rebuilt from the session's events each time a report is built instead of reusing the copy frozen at the first error.
- **Failed responses survive a reload.** The first 200 characters of a failed response lived only in memory, so they were gone after a reload and from every saved ticket. They are now stored on the request itself.
- **Storage is shown as it was when the bug happened.** The localStorage / sessionStorage / cookie snapshot was read when the report was built, so a saved ticket reopened days later showed that day's storage. It is now taken at the first error (or when the capture stops) and kept with the session.
- **The report URL is the page the bug happened on.** It was the page the capture started on, so a bug two pages in was reported under the landing page. The URL is now the page of the first failure (or the last page visited), and the Info tab adds "Started on" when they differ.
- **Page-load requests carry their real time.** Requests from before the capture were all stamped with the moment the capture started; they now keep when they actually ran.
- **The recommended MCP setup no longer hides your reports.** Every published setup command carried `--dir ./bug-reports`, which turns off the server's search of Downloads and Desktop, so a report just exported from the extension gave `count: 0`. The docs, both READMEs, the website, the exported file's AI tab and the hand-off prompt now use `claude mcp add -s user tracebug -- npx -y tracebug mcp` (`-s user` makes it work in every project; native Windows gets a `cmd /c` note). `--dir` is documented as "limit to one folder".
- **No more "Restored draft" with the previous bug's title.** The ticket saved its untouched auto-filled title as a draft on close, so the next capture within the hour opened under the old title. Drafts are now saved only when you actually edit, and a successful Export replay or .zip clears them.
- **The in-page toolbar's Record follows your Tab / Desktop choice.** In the extension it always asked for Desktop, so every toolbar recording opened the share picker even with Tab mode set up. It now uses the popup's stored choice (Desktop on Firefox, which has no tab capture).
- **The welcome page copies the real setup command.** It offered a bare `npx tracebug mcp`, which only waits on stdin. The Alt+B shortcut is described as what it does (screenshot + ticket), not "start a capture".
- **Fix with AI uses the ticket as you edited it.** It sent the auto-generated title and ignored your description; it now applies your title, and an edited description is included as "Reporter's description".
- **The title and summary name the action that caused the bug.** Both used the session's last action, so a coupon crash followed by a click on "Place order" was titled "Place order Fails" and summarized "thrown when clicking Place order". They now use the last action before the first error or failed request, with a neutral title when nothing came before it. Found in the first playground run, where Claude Code had to point out the mismatch.
- **The root-cause hint for "Cannot read properties of undefined" no longer prescribes optional chaining.** It now says to find out why the value is missing (a config entry, a failed request, a wrong key) and to add a guard only where the value can really be absent. "Add `?.`" is the fix that silences the crash ("SAVE20 applied — NaN% off") instead of fixing it.
- **A capture where nothing failed says so instead of inventing a cause.** With no error and no failed request, the root-cause hint claimed "Click on 'Place order' did not trigger any observable effect" without checking anything, right after the click had visibly placed an order. It now reads "No errors or failed requests were captured — last action was clicking 'Place order'" and points at the reporter's description. The Fix with AI prompt shows a "No errors captured" section in place of a cause, and the MCP investigation guide tells the agent to read the description or ask what looked wrong, and marks the generated test as low value for such a report. No error is not proof of no bug: a wrong total throws nothing, which is what the description is for.
- **Slow typing is one step, not five.** A field's value is recorded after each 300 ms pause, so typing a coupon produced `Type "SA"`, `Type "SAV"`, … `Type "SAVE20"` in the repro steps and five `fill()` calls in the generated test. Consecutive typing in the same field (no click, navigation or error in between) now collapses to its final value: `Type "SAVE20" in "coupon"`.
- **A clean capture's title says so:** `No errors captured: Click "Apply coupon" → …` instead of `Session: …`, with repeated actions shown once.
- **"Dead click" now means a re-click, not a pause.** A click was flagged dead whenever the next captured event came more than 1.5 s later, so stopping to read a message marked a working button as dead and raised the agent's guide to "[HIGH] … where the user got stuck". It now takes a second click on the same element 1.5–8 s later.
- **The timeline lists each request once.** The browser's Resource Timing copy of a fetch showed up as a second, method-less row (" /api/orders → 201"); the timeline now drops it the way the Network tab already did.
- **One workflow in every agent prompt.** The hand-off card, the exported file's AI tab, the MCP `/tracebug:debug_bug_report` prompt and Fix with AI said different things (one "propose a fix", one "implement the fix", only one mentioned the generated test). They now share `src/exporters/agent-workflow.ts`: gather the evidence, find the root cause, explain the fix, ask for approval before editing, add or update a regression test, run it red → green.
- **`get_playwright_test` explains a missing test correctly** (no replayable actions, or a pre-1.9 export) and its run steps now include installing Playwright, starting the dev server and setting `BASE_URL`, so a spec doesn't silently test the captured staging site.

- **The exported report has the new look.** The `.html` replay was still on the old indigo theme with a bug-emoji logo; it now uses the coral palette in light and dark, the prompt logo, and dark text on coral buttons.
- **One setup command everywhere.** The hand-off prompt and the exported file’s AI tab still said `claude mcp add tracebug …` (current project only) while the card above them said `claude mcp add -s user tracebug …`. All three now use the same user-scoped command.
- **Copied GitHub issues and Jira tickets no longer repeat themselves.** When the description box still held its auto-filled summary, it was printed above the full generated body, so the cause, actions, steps and environment appeared twice. The description is included only when you wrote or edited it.
- **The AI prompt’s “recent successful calls” are API calls.** It listed script, style and image loads (`similar-menu.js → 200`), which tell an agent nothing; those are left out now.
- The AI prompt no longer points at a “cloud link” for screenshots; it says they are in the exported .html report.
- **The in-page panels get their theme again.** Since 1.11.3 the theme was applied before TraceBug’s UI existed on the page, so none of its colours reached it: the ticket’s More menu was see-through over the panel behind it, and the UI fell back to hard-coded dark colours whatever theme was chosen. The theme is now applied once the UI is mounted (light by default; the ticket’s theme button switches it).
### Changed

- **Private by default, everywhere a report goes.** Before, the page URL kept its query string in local exports and the AI prompt (only the cloud upload masked it), form submits kept hidden fields such as CSRF tokens, a token pasted into a plain field was kept as typed, voice notes were not scrubbed, and the storage snapshot listed the value of every cookie on the host (on `localhost`, other local apps' too). Now: one URL redactor masks sensitive query **and fragment** params (`#access_token=…`) in request URLs, the page URL, link hrefs, form actions and the DOM replay; form submits leave hidden fields out and say how many; typed values, form values and voice notes get the same token-shape scrub as console output; cookies are listed **by name only** unless `captureCookieValues: true`. The Evidence block says "cookie values (names only)", "N hidden form fields" and "HttpOnly cookies and IndexedDB" under Not captured, and counts tokens masked in typed values.
- **`maxEvents` defaults to 500 (was 200), and dropped events are counted.** The session records how many of its oldest events were evicted (`droppedEvents`), including when full browser storage forces a trim, so a report can say its lead-up is incomplete.
- **New look.** The in-page toolbar, ticket, settings, player and welcome pages and the popup use a coral accent on a dark theme, and the popup’s Auto theme follows your system setting.
- **The "Open in your AI agent →" link after an export stays until you dismiss it** (it vanished after 8 s, and with it the only way to the setup card).
- **`list_bug_reports` returns the newest report first**, so "debug the latest report" means the latest.
- **Setup card:** the Cursor snippet is now valid JSON you can paste, a Windsurf tab is added, and each tab says where its snippet goes.
- Copy: the popup subtitle names the surface ("Records a window or screen" in Desktop mode); the Tab/Desktop switch no longer flashes Desktop on open; the AI tab no longer claims keys live in `localStorage`; quickstart button names match the UI.
```
